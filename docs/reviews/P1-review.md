## FIX list

1. **Medium, accessibility, mechanical.** Focus is lost when a button is swapped for a different one. Compose creates a new DOM node because the two buttons sit at different call sites: `ui/lesson/SimFrame.kt:76-80` (Play to Pause: a keyboard user must Tab again from the top to press Pause), `ui/lesson/PredictOutput.kt:166-175` ("Run it to check" to "Try again"), `ui/lesson/FixBug.kt:76-80` ("Want a nudge?" to "Show me one fix", which then vanishes). WCAG 2.4.3. Fix: one `Button` call whose `text` and `onClick` change (keeps the node); when a button must disappear, move focus to the revealed box or to Reset. Inferred from Compose semantics, not run in a browser: re-test with Tab and Enter after the change. The 38-stop Tab walk in `P1-acceptance.md` never activated these.
2. **Medium, spec, mechanical (architect confirms stage vs frame).** `ui/lesson/SimFrame.kt:49-60`: `box-sizing: border-box` plus a 1 px border makes the 16:9 stage about 718 x 404 (`ks-12-lesson-components-b.png`: 33 to 751 px wide, 406 to 810 px high), not 720 x 405. `docs/02` 4.5 relies on exactly 720 x 405 so that world unit = CSS px (44 px bodies). Fix: size the stage, not the bordered frame, to `layout.lesson.wide` (content-box, or draw the border as an inset ring) and re-measure 720 x 405.
3. **Medium, contrast, owner (architect).** Hover and pressed state layers are not gated and break 4.5:1. `ui/core/Button.kt:70-76` lays 8% (hover) and 12% (pressed) of the content colour over the fill. I recomputed with the same sRGB mix (scratch script, not in the repo). Tonal (ink on tint with ink overlaid): hover fails for 9 of 17 branches (`testing` 4.07, `ui` 4.26, `kotlin` 4.28, `dsa` 4.33, `architecture-data` 4.19, `networking` 4.20, `tools` 4.20, `kmp` 4.44, `profiling` 4.44) and pressed fails for 10 (`testing` 3.84, `networking` 3.97, `tools` 4.00, `ui` 4.01, `architecture-data` 4.01, `kotlin` 4.08, `dsa` 4.11, `kmp` 4.22, `profiling` 4.21, `daa` 4.45). Filled (white on ink with white overlaid): hover passes everywhere (min 4.52 `tools`); pressed fails for `tools` 4.20, `architecture-data` 4.29, `networking` 4.42, `testing` 4.45, `kotlin` 4.46. Text kind passes (min 4.54). `docs/02` section 7 asks for 4.5:1 on every interactive element, and the `check-tokens.py` rule "never relax 4.5" covers resting pairs only. Decide: smaller layer percentages, darker inks, or a different state treatment (for example a thicker outline or text underline on hover/pressed for Tonal). Then add these pairs to `scripts/check-tokens.py`. `P1-acceptance.md` row "Hover, focus, pressed" checked behaviour, not contrast.

Fix: add patterns for digits plus `px|rem|em|ms|s` inside quotes, `rgba?\(|hsla?\(`, `Colors?\.[A-Z]`, quoted CSS colour names, and apply the `0.px`/`100.percent` exemption to the matched token, not the line.
