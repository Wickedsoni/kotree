## Facts verified against official page bodies (fetched 21 Oct 2026)

Kotlin (page source `kotlin-web-site/docs/topics`, the text behind kotlinlang.org):
- enum-classes: constants listed in the body separated by commas; built-in `name` and `ordinal` ("position (starting from `0`)"); `entries` is "a specialized `List`" and standard collection APIs work on it (`size`); "When you use all enum constants in a when expression, you don't need an `else` branch"; `valueOf()` throws `IllegalArgumentException` when no constant matches; `enumValues<T>()` returns an array.
- sealed-classes: "All direct subclasses ... are known at compile time. No other subclasses may appear outside the module and package"; direct subclasses must be in the same package; with `when` expressions the compiler "check[s] exhaustively" and no `else` is needed.
- control-flow: "If you use `when` as an expression, you must cover all possible cases ... the compiler throws an error"; Boolean, enum and sealed subjects need no `else` when covered.
- object-declarations: define a class and create an instance in a single step, "useful for implementing singletons"; "initialization ... is thread-safe and done on first access"; companion objects give class-level functions and properties, called with the class name as qualifier; "A companion object is initialized when the corresponding class is loaded"; plain object `toString()` shows name plus hash; `data object` returns the actual name; the `data object` printing example prints `MyDataObject`.
- generics: classes can have type parameters; type arguments can be inferred; type safety checks are compile time; instances do not hold type arguments at run time; `Foo<Bar>` and `Foo<Baz?>` are erased to `Foo<*>`; `ints is List<Int>` is prohibited; a check against `List<*>` is allowed and "items are typed as `Any?`".
